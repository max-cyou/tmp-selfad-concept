# Personal Attack-Defense CTF: концепция формата

> Описание формата соревнования, который проводит SelfAD.

## 1. Описание самого формата
Во время начала соревнований, участникам выдаются уязвимые сервисы -- например, один их них это веб-сервер на Python. Участнику открывается доступ к двум репозиториям на self-hosted gitea: read-only исходный код уязвимого сервиса и репозиторий с пустым файлом `exploit.py`, в который необходимо записать код эксплойта, вытягивающего флаги из уязвимого сервиса.

После успешной атаки (push в репозиторий эксплойта) участнику открывается defense-репозиторий (все это происходит в рамках одного сервиса) -- копию уязвимого сервиса, где он должен исправить уязвимость, и после push проверяется функциональность сервиса и сама уязвимость.

Штраф может быть получен за мусор в выводе эксплойта и за неудачные попытки, что регулируется организатором в админ-панели.

Таким образом, формат Attack&Defense адаптируется под соло-игру.

## 2. Организация CTF
Организатор, прежде чем начать соревнование, должен сделать следующие вещи:
1. Установить сам SelfAD (платформу)
2. Настроить админку и оформление в `/setup`
3. Настроить штрафы и правила участия
4. Создать сервисы, залить на них код с DockerFile
5. Создать и залить эталонный эксплойт для проверки defense-репозиториев, чекер на функциональность и скрипт для засыла флагов в уязвимые сервисы (при проверке attack-репо)
6. Настроить зависимости для участников в attack-репо
7. Запустить CTF

## 3. Безопасность
DockerFile защищены от записи, чужие репо недоступны для просмотра, стоят таймауты и ограничения для attack-репо.
